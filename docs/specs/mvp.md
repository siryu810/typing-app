# Reply Day — MVP 実装仕様

ゲームルールの正本は [`docs/mvp-spec.md`](../mvp-spec.md) を写したもの。この文書は実装時の追加事項（制限時間、ローマ字別表記、D1、匿名ID、クライアント完結の入力）を足したもの。企画フェーズの「バックエンドはMVP外」は、この実装スコープでは **問題とプレイ結果だけ D1 に保存** する方針に置き換える。

UI の正本は [`mockups/final.html`](../../mockups/final.html)（案C構成＋案Bの親しみやすさ）。

---

## 1. 概要

- **タイトル:** Reply Day
- **サブ:** 今日も返信します
- **舞台:** 今どきのWebサービス企業「株式会社カイト」。主人公はフルスタックでWebアプリを開発する部署に配属されたエンジニア
- **体験:** 社内のオリジナル業務チャット「カイトチャット」に依頼が届き、決められた返信文をローマ字で打って送る。速さ・正確さでゲーム内年収が上がる
- **UIコンセプト:** Slackのような業務チャット × タイピングゲーム。Slackの複製ではなく、カイト社のチャットツールとしてデザインする

主人公はカタカナ語やIT用語を使うのが好きで、少しユーモアがある。ただし実際の業務チャットとして不自然にならない範囲に留める。

プレイを進めると「新米 → 慣れてきた → つよつよ」の成長感が得られる。  
成長は難易度名・フレーバー・返信の長さと業務リアリティで表現する。アカウントの成長保存はMVP外（匿名プレイ結果の保存のみ）。

---

## 2. MVPに含むもの / 含まないもの

### 含む

- ホーム画面
- 難易度選択画面（初級・中級・上級）
- タイピング画面（相手メッセージ＋自分の返信日本語＋ローマ字判定）
- 結果画面（年収＋速度・正確性・ミス数・最大連続入力数）
- 制限時間90秒。返信完了ごとに報酬加算
- 正しく入力した文字・ミスタイプ・現在位置の視覚化
- 問題とプレイ結果の D1 保存（キー入力の都度通信はしない）
- 匿名ID（localStorage）

### 含まない

- ログイン、ランキング、オンライン対戦
- 高度なタイピング分析（苦手キー、入力回数、ミス率、苦手な指、キー遷移など）
- 詳細な難易度カスタム
- URLなど入力負荷が高すぎるテキスト
- キー入力ごとの API
- GitHub Actions

将来の「タイピング分析」画面は、結果・ホームから辿れる余地（非活性 / 「準備中」）だけ残す。中身は作らない。

## 3. ゲームフロー

```
ホーム → 難易度選択 → タイピング →（時間切れ）→ 結果
結果 → もう一度 → 難易度選択
結果 → ホーム
```

1. **ホーム**  
   世界観の一言と「業務を開始する」。
2. **難易度選択**  
   新米 / 慣れてきた（UI表示は「一人前」） / つよつよ。制限時間と返信の傾向を短く示す。
3. **タイピング**  
   90秒のタイマー開始。キューから相手メッセージが1件ずつ新着する。返信のローマ字を打ち切ると自動送信され、報酬が加算され、次のチャットが届く。
4. **結果（退勤）**  
   時間切れで退勤。入力途中の返信は未送信とし、スコアに含めない。

制限時間: 全難易度 **90秒**。難易度差は文面の長さ・記号量・口調で出す。

開始時に `GET /api/problems?difficulty=` で問題一覧を取得する。シャッフルはクライアントで行う。終了時に `POST /api/plays` で結果を1回だけ保存する。

## 4. タイピングルール

- 相手メッセージは **日本語** で表示する
- これから送る返信は **日本語** とその直下に **正規化したローマ字を1通り** 並記する  
  例: `確認します。` → `kakuninshimasu.`
- ユーザーはローマ字を入力する。判定対象はローマ字側
  - 入力済みの正解: 落ち着いた色
  - ミスタイプ: 赤
  - 現在位置: カーソル / ハイライト
  - 未入力: 薄い色
- ローマ字を最後まで正しく打ち切ったら **自動送信**（送信ボタンは見た目用）
- 英数字・記号（`@` `#` `*` `-` `` ` `` など）はそのままのキーで打つ
- 表示は正規化1通り。**入力は一般的な別表記も許容**する（`shi` / `si`、`chi` / `ti`、`tsu` / `tu`、`fu` / `hu`、`sha` / `sya` など）。詳細は [ADR: ローマ字別表記](../adr/0001-romaji-alternates.md)
- 判定は **クライアントのみ**。キー入力で API は呼ばない

## 5. 難易度

### 初級：新米エンジニア

- 短い返信、簡単なやり取り、記号少なめ
- 社会人としてまだ初々しい雰囲気

例

- 相手: 「PRのレビュー、あとで見てもらえますか？」
- 返信: 「確認します。少々お待ちください。」
- ローマ字: `kakuninshimasu. shoushou omachikudasai.`

### 中級：慣れてきたエンジニア（UI: 一人前エンジニア）

- 少し長めの返信、`@` メンション、Issue / PR、Markdown、英数字、記号、技術用語
- 仕事に慣れてきて、自信が出てきている雰囲気

例

- 相手: 「@kaito PR #128 のレビューお願いできますか？」
- 返信: 「@tanaka 見ました。LGTMです。#128 はマージして大丈夫です。」
- ローマ字: `@tanaka mimashita. LGTMdesu. #128 ha maaji shite daijoubudesu.`

### 上級：つよつよエンジニア

- 長め・複数行、Markdown、引用、技術用語、英数字、記号を多く含む
- かなり仕事ができ、自分に強い自信を持っている雰囲気
- カタカナ語・IT用語を自然に混ぜる。長いURLは使わない

例

- 相手: 「決済APIがタイムアウトしてます。優先度高めです。」
- 返信:

```
再現できた。`checkout` のリトライ3回目で落ちてます。
- 暫定: タイムアウトを8sに延長で回避
- 本対応: 冪等キー必須化します。こちらで巻き取ります
```

### チャット題材の方針

実際のIT業務でありそうなやりとりを使う。

- 確認、レビュー依頼、バグ報告、進捗、質問、顧客・他部署への連絡
- `@` メンション、Issue / PR番号、Markdown風、技術用語、英数字・記号
- 仕様変更、問い合わせ、トラブルが頻繁に起きる職場
- 少しのユーモアは可。業務チャットとして不自然にならない範囲
- URLのように入力負荷が高すぎるものは避ける

口調はカイト社の新米／慣れてきた／つよつよに合わせる。

## 6. スコア（ゲーム内年収）

メインスコアは **ゲーム内年収**。

- 開始時の表示年収（基本給）
  - 初級: 300万
  - 中級: 450万
  - 上級: 600万
- 返信1件を送り終えるごとに報酬を加算し、合計を「現在年収」として表示する

件ごとの報酬の考え方

- 基礎額: 初級 +12万 / 中級 +22万 / 上級 +38万
- その返信の入力速度（その件のWPM相当）と正確率で増減
- ミスが多いと減額。ほぼ完璧なら少し上振れ

実装上の増減:

- 速度倍率: その件の WPM が 20 未満 0.70、40 未満 0.85、60 未満 1.00、80 未満 1.10、それ以上 1.20
- 正確率倍率: 100% で 1.15、95% 以上 1.05、90% 以上 1.00、80% 以上 0.85、それ未満 0.70
- 報酬（万）は基礎額 × 速度倍率 × 正確率倍率を四捨五入した整数。最低 1 万

ゲーム終了時は年収のほか、次を表示する。

- 入力速度（セッション全体のWPM）
- 正確率
- ミス数
- 最大連続入力数（正しく打ったローマ字の最長ストリーク）

COMBO は正解キーの連続。ミスでリセット。成長ゲージはセッション中の送信件数から算出する（目安 8 件で 100%）。

セッション全体の WPM は、正しく消費したローマ字数を 5 で割った語数を、経過分（分）で割る。正確率は `correct / (correct + misses)`。

## 7. 主要画面

### ホーム

- タイトルとカイト配属の一文
- 難易度選択へ進む CTA
- タイピング分析は「準備中」程度の導線のみ

### 難易度選択

- 初級・中級・上級の3カード
- 成長段階（新米 / 一人前 / つよつよ）が分かること
- 制限時間と返信の傾向の短い説明

### タイピング（最重要）

表示するもの

- 業務チャット（相手からの最新メッセージ、過去に送信した返信）
- これから送る日本語返信
- ローマ字入力対象（正解 / ミス / 現在位置 / 未入力）
- 現在年収、WPM、正確率、ミス数、残り時間
- COMBO（または最大連続入力を意識した表示）

主役は「業務チャットへの返信」と「タイピング」。メトリクスが入力対象より目立ちすぎないこと。PCブラウザ主対象。

レイアウトは最終HTMLどおり（左レール: 年収・COMBO・成長・WPM・正確率・ミス・残り / 右チャット / 下入力）。

### 結果

- 最終年収を主表示
- WPM、正確率、ミス数、最大連続入力数
- もう一度（難易度選択へ）/ ホーム
- タイピング分析は非活性または「準備中」

## 8. UI / UX方針

- 白をベースにした、今どきのIT企業らしい見た目
- 複数のアクセントカラー、ポップ、モダン
- タイピング中は文章への集中を邪魔しない
- オリジナルのカイトチャット。Slackそのものはコピーしない
- 年収・速度・正確率・残り時間・COMBOはプレイ中も確認できるが、チャットと入力より強くしない
- PCブラウザ主対象。狭い幅でも大きく崩れない

**採用したUI:** 案Cの構成（左サイドバー＋右チャット＋下入力）に、案Bの親しみやすさ（明るい本文、色付きアバター、角丸）を足したハイブリッド。参考モックは `mockups/final.html`。

## 9. データと API

D1 はローカルと本番を分離する。スキーマ変更は Git 管理の migration。

### テーブル

- `problems` — difficulty、相手名、incoming 日本語、reply 日本語、読み（ローマ字生成用）
- `plays` — anonymous_id、difficulty、salary、wpm、accuracy、misses、max_combo、sent_count、created_at

### API

- `GET /api/problems?difficulty=` — その難易度の問題一覧（シャッフルはクライアントでも可）
- `POST /api/plays` — 終了時に結果を1回保存。body に `anonymousId`

キー入力では API を呼ばない。匿名IDは初回アクセスで生成し `localStorage` へ。ログインなし。個人情報なし。

問題は難易度ごとに複数件（目安 各8件前後）をシードする。

---

## 10. 技術構成

- React SPA + Hono API を **1つの Cloudflare Worker** に載せる（`@cloudflare/vite-plugin`）
- ツールチェインは Vite+（`vp`）。`just check` は `vp check && vp test && vp build`
- Node と package manager は `vp` に任せる。ESLint / Prettier は個別導入しない

## 11. 将来（MVP外）

各プレイで将来的に記録・分析できるようにする想定。

- 苦手キー（入力回数、ミス回数、ミス率）
- 苦手な指
- 苦手な動き（連続する2キー程度のキー遷移）

MVPでは画面追加の余地だけ残す。高度な分析機能は作らない。
